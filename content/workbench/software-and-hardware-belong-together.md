Most of the tools on this site run in a browser, and most of what ends up on the bench is hardware. They work better together: software can make hardware easier to set up, test, and understand, and hardware gives software something real to do.

## Topics in this note

- Browser tools that help with hardware jobs
- Reading data from devices into simple tools
- Keeping things local and private by default
- Building small, focused tools instead of big platforms
- Where a desktop app makes more sense than a browser

This is a direction for OrgToolTank, not a finished feature list.

## What I learned

A small tool that solves one real problem gets used more than a big one that tries to do everything.

## What I’d do differently

I’d start from the real-world job and work back to the software, not the other way around.

## Tools & Parts (examples)

- A computer with a current browser
- USB cables and adapters
- Microcontroller board for experiments
- Notebook for what the tool actually needs to do
