Newer isn’t always better. Some older operating systems and programs still do one job really well, run fine on hardware that newer software has left behind, or open files nothing current can read anymore.

The trick is using them on purpose: knowing what they’re good for, keeping them away from the open internet when they no longer get security updates, and getting them from places you’re actually allowed to get them.

## Topics in this note

- When an older program is still the right tool
- Running old software on old hardware vs. in a virtual machine
- Keeping unsupported systems offline or isolated
- Using your own original install media and license keys
- Getting old files out into formats current software can open

This page is discussion only. I don’t host or link to old software. Use installers you own or that the publisher still offers.

## What I learned

A lot of “obsolete” software is fine for the one job it was built for. The risk comes from treating it like a modern, connected system.

## What I’d do differently

I’d make a copy of the original install media and keys the first time, instead of hunting for them when the machine needs a reinstall.

## Tools & Parts (examples)

- Original install media or the publisher’s download
- License keys you own
- A spare drive or virtual machine for testing
- A way to move files over (USB drive or local network)
